What Is PulseBoard?

PulseBoard is like a security camera for your websites and apps. Instead of waiting for a customer to tell you "your site is down," PulseBoard checks automatically and tells you first.

It runs on your computer using Docker. No cloud account needed. No monthly fees. Just download, start, and monitor.

Who Is This For?

  • Small business owners — Monitor your website uptime
  • Freelancers — Watch client websites
  • Students — Learn how monitoring works
  • Developers — Monitor your APIs and microservices
  • Anyone — Who wants to know if their site is up

Step 1: Install Prerequisites

You need 3 things on your computer. Click the links to download.

1

Install Docker Desktop

Download from docker.com. Install it. Open it. Wait for it to say "Docker is running."

2

Install Git

Download from git-scm.com. Install with default settings.

3

Verify Installation

Open Terminal (Mac) or Command Prompt (Windows) and run:

docker --version
git --version

You should see version numbers. If you see "command not found", the installation didn't work.

Step 2: Download PulseBoard

1

Clone the repository

Open Terminal and run:

git clone https://github.com/cijostany6-bit/pulseboard.git
cd pulseboard
2

Start PulseBoard

Run this single command:

docker-compose up -d

Wait 10 seconds. Docker will download and start 8 containers.

3

Verify it's running

./scripts/smoke-test.sh

You should see a visual dashboard with green and red status cards.

This stops all containers and cleans up. Your data will be deleted.

How To Use PulseBoard

PulseBoard watches your websites and services. Here's how to add your own.

Add A Website To Monitor

curl -X POST http://localhost:9082/services \
  -H "Content-Type: application/json" \
  -d '{"name":"my-website","url":"https://your-website.com","interval":30000}'

Check Its Health Manually

curl -X POST http://localhost:9082/check/my-website
        
Record Metrics

        

          
          
curl -X POST http://localhost:9083/metrics \
  -H "Content-Type: application/json" \
  -d '{"service":"my-website","cpu":15.0,"memory":40.0,"responseTime":120}'

        


        
Create An Alert Rule

        

          
          
curl -X POST http://localhost:9084/rules \
  -H "Content-Type: application/json" \
  -d '{"service":"my-website","condition":"status == unhealthy","channel":"slack"}'
        
View Alert History

        

          
          
curl http://localhost:9084/history

The 5 Services Explained Simply

          
PulseBoard has 5 small programs (services) that work together. Here's what each one does.

        


        

          

            
Port 9080

            
API Gateway

            
The front door. Everyone enters through here.

          

          

            
Port 9081

            
Auth Service

            
The security guard. Checks if you're allowed in.

          

          

            
Port 9082

            
Health Checker

            
The doctor. Checks if all services are healthy.

          

          

            
Port 9083

            
Metrics Collector

            
The note-taker. Records CPU, memory, speed.

          

          

            
Port 9084

            
Alert Manager

            
The alarm. Screams when something breaks.

          

        


        

          
How They Talk To Each Other

          
Imagine 5 robots in a room:

          
    
            
  • Health Checker (doctor) checks all robots and writes results on a whiteboard (Redis)
    • 
            
  • Alert Manager (alarm) reads the whiteboard. If it sees "Robot 2 is broken," it screams
    • 
            
  • Metrics Collector (note-taker) writes down numbers in a notebook (PostgreSQL)
    • 
            
  • API Gateway (front door) lets you see everything on a screen (dashboard)
    • 
            
  • Auth Service (security guard) checks if you're allowed to look at the screen
    • 
          

        


        

          
What's Inside (Database & Queue)

          

            

              
Port 5432

              
PostgreSQL

              
The notebook. Stores users, metrics, alerts.

            

            

              
Port 6379

              
Redis

              
The whiteboard. Passes messages between services.

            

          

        

      


      
      

        

          
Troubleshooting

          
Common problems and how to fix them.

        


        

          "port already allocated"
          
Something else is using that port. Run: lsof -i :9080 to find what's using it. Either stop that program or change the port in docker-compose.yml.

        


        

          "Docker daemon not running"
          
Docker Desktop is not open. Open Docker Desktop and wait for it to say "Docker is running." On Mac, you can also run colima start in terminal.

        


        

          "Connection refused" or "HTTP 000"
          
Services need 10-15 seconds to start. Wait a bit and try again. Or check logs: docker-compose logs health-checker

        


        

          "Container unhealthy"
          
Check the logs: docker-compose logs <service-name>. Common cause: missing dependencies or port conflicts.

        


        

          "npm install failed"
          
The Dockerfile couldn't install packages. Rebuild without cache: docker-compose build --no-cache

        


        

          "Cannot connect to Docker"
          
Make sure Docker Desktop is running. Check with: docker info. If it fails, restart Docker Desktop.

        


        

          "Permission denied" on scripts
          
Make scripts executable: chmod +x scripts/*.sh
        

          "Page not loading at localhost:3000"
          
Hard refresh your browser (Cmd+Shift+R on Mac). Or try incognito mode. The frontend container might need a rebuild: docker-compose build --no-cache frontend && docker-compose up -d frontend
      


      
      

        

          
Frequently Asked Questions

        


        

          
What is PulseBoard?

          
PulseBoard is a free, open-source tool that monitors your websites and apps. It checks if they're up, collects performance numbers, and alerts you when something breaks. Think of it as a security camera for your software.

        


        

          
Do I need to know coding to use it?

          
No. You just need to install Docker and run one command. The dashboard is visual — green means healthy, red means broken. No coding required.

        


        

          
Is it free?

          
Yes. 100% free and open source. It runs on your computer. No subscriptions, no cloud costs, no monthly fees.

        


        

          
Can I monitor my own website?

          
Yes. Add your website URL using a simple curl command. PulseBoard will check it every 30 seconds and alert you if it goes down.

        


        

          
What if I don't have Docker?

          
Docker is required. It's free to download from docker.com. It runs on Mac, Windows, and Linux. The installation takes about 5 minutes.

        


        

          
Can I use this for my business?

          
Yes. It's open source (MIT license). You can use it commercially. Many small businesses use it to monitor their websites.

        


        

          
How is this different from UptimeRobot or Pingdom?

          
Those are cloud services that cost money and only check if your site is up. PulseBoard also collects metrics (CPU, memory, response time), has alerting rules, and runs on your own computer for free. Plus you can customize it however you want.

        


        

          
Can I deploy this to AWS?

          
Yes. The project includes CloudFormation templates and a Jenkins pipeline. But for most users, running it locally with Docker is enough.

        


        

          
What happens to my data?

          
All data stays on your computer. Nothing is sent to the cloud. When you stop PulseBoard, the data is deleted (unless you configure persistent storage).

        


        

          
How do I update PulseBoard?

          
Run: git pull origin main then docker-compose up -d --build
        

          
Where can I get help?

          
Open an issue on GitHub: github.com/cijostany6-bit/pulseboard/issues
